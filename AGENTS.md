# NixOS Configuration Agent Rules

This workspace contains a NixOS system configuration managed via flakes. When acting on this directory, please adhere to the following rules:

## 1. Modular Configuration Structure
- Keep `configuration.nix` clean. Place new configurations into the appropriate specialized modules inside the `modules/` directory:
  - `packages.nix` for user and system packages
  - `desktop.nix` for UI/desktop environment settings
  - `networking.nix` for network configurations
  - `services.nix` for system services/daemons
  - `aliases.nix` for shell aliases
  - `overlays.nix` for nixpkgs overlays
  - `shell.nix` for shell environments and related setups
- If a new domain of configuration emerges, create a new file in `modules/` and import it in `configuration.nix`.

## 2. Flake Management
- `flake.nix` is the entry point. It defines inputs (like `nixpkgs`, `antigravity-nix`, `helium`) and outputs.
- When adding new repositories or third-party flake inputs, add them to `flake.nix` and pass them appropriately into the configuration.

## 3. Do Not Edit Generated Files
- **NEVER** edit `hardware-configuration.nix` directly, as it is automatically generated by `nixos-generate-config`. Any system-specific hardware quirks should be managed either by regenerating the file or adding overrides in `configuration.nix`.

## 4. Applying and Testing Changes
- After making edits, remind the user to test or apply the changes using the flake setup.
- To test changes (doesn't modify bootloader):
  `sudo nixos-rebuild test --flake .#nixos`
- To apply changes permanently:
  `sudo nixos-rebuild switch --flake .#nixos`
- To update flake inputs:
  `nix flake update`

## 5. Nix Language Best Practices
- Ensure all configurations are valid Nix expressions. Watch out for missing semicolons (`;`) at the end of statements.
- Remember that the primary user `amiel` uses the `fish` shell. Assume any shell-specific tweaks should be compatible with `fish`.
